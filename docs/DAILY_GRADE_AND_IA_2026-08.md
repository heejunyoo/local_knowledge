## 0. 한 줄

> **"오늘의 나"는 도구 모음이 아니라 하루를 기록하는 것 하나다.**
> 자동 수집(수면·활동)과 수동 입력(식사)을 종합해 하루에 등급을 매기고,
> 노트·지식은 그 하루에 맥락으로 붙되 **점수에는 들어가지 않는다.**

## 1. 제품 정의

궁극 목표는 **개인 비서**다. 그 1단계가 "하루를 객관적으로 등급 매기는 것"이다.

| 입력 | 공급 방식 | 이번 범위 |
|---|---|---|
| 수면 | 워치 → iOS 단축어 → `/api/health/ingest` | ✅ |
| 활동 (운동 + 일상 활동) | 같음 | ✅ (걸음·활동에너지는 스키마 확장 필요) |
| 식사 | **수동 입력** — 간소화가 핵심 | ✅ (ingreed 제품 검색 1단계 완료) |
| 노트 자동 분류 | 앱 내 캡처 | ✅ 분류는 하되 **등급에는 미반영**(§2.4) |
| 녹음 → 요약 → 분류 | — | ❌ **범위 밖**(2026-08-20 오너 결정). 확장 시 §6-3 참조 |
| Graph RAG 채팅 | — | 다음 단계 |

## 2. 하루 등급

### 2.1 축 — 선언: "하루의 몸 상태를 만드는 입력"

| 축 | 내용 | 공급 |
|---|---|---|
| **회복** | 수면 | 자동 |
| **활동** | 계획된 운동 **+ 일상 활동**(걸음수·활동에너지) | 자동 |
| **섭취** | 에너지·단백질·당·나트륨·포화지방 | 수동 |

- **"운동"이 아니라 "활동"이다.** 운동을 안 해도 많이 걸은 날은 다르다.
- **체중은 축이 아니다.** 입력이 아니라 결과라 층위가 다르다 → 추세 지표로 분리.
- 기분·스트레스·음주·수분은 이번 범위 밖. 주관 입력이라 축의 성격이 다르다.

### 2.2 ⭐ 결측을 두 종류로 가른다 — 이 설계의 중심

**ingreed 의 "축이 없으면 나머지로 재정규화"를 그대로 쓰면 안 된다.**

ingreed 에서 축 결측은 *제조사가 신고를 안 한 것*이라 사용자와 무관하다.
하루에서 축 결측은 **사용자 행동 그 자체**다. 그대로 옮기면 이렇게 된다.

```
6시간 자고 기록함   → 회복 축 감점
6시간 자고 기록 안함 → 회복 축 제외 → 남은 축이 좋으면 A
```

**나쁜 날을 기록하지 않을수록 등급이 올라간다.** 자기기만 기계가 된다.

| 결측 종류 | 정의 | 예 | 처리 |
|---|---|---|---|
| **구조적** | 사용자가 선택적으로 감출 수 없다 | 워치를 안 찼다 → 수면 데이터 자체가 없음 | **재정규화한다.** 단축어가 자동 POST 하므로 골라서 숨기지 못한다 |
| **행동적** | 안 쓰면 안 들어온다 | 식사를 기록하지 않았다 | **재정규화하지 않는다.** `ratable: false` 로 두고 추세·비교에서 제외 |

> **자동 축은 재정규화, 수동 축은 금지.** 이 한 줄이 나머지를 결정한다.

### 2.3 ingreed 에서 가져오는 것 / 안 가져오는 것

| 가져온다 | 왜 |
|---|---|
| `ratable` — 같은 잣대로 비교 가능한가 | 기록이 불완전한 날을 추세에서 빼는 데 그대로 쓴다 |
| `confidence` 0~1 | 입력이 적은 날은 등급 옆에 "추정" 표시 |
| 축별 `breakdown` + `reasons`(사실 진술 한 줄) | 등급이 왜 그런지 답할 수 있어야 한다 |
| **순수 함수 · LLM 미사용** | 같은 입력에 같은 등급. 재현되지 않으면 등급이 아니다 |

| 안 가져온다 | 왜 |
|---|---|
| 축 결측 시 **무조건** 재정규화 | §2.2 |
| **모집단 분포로 등급 컷 잡기** | 사용자가 1명이라 분포가 존재하지 않는다 |

### 2.4 노트·지식은 등급 점수에 넣지 않는다 (2026-08-20 오너 승인)

무엇을 측정할지 물으면 전부 무너진다.

| 후보 | 왜 안 되나 |
|---|---|
| 노트 개수 | 의미 없는 노트 10개면 A. 즉시 게임화 |
| 분류 다양성 | 같음 |
| 노트의 "질" | **LLM 판단 → 재현 불가.** 분류 모델·프롬프트가 바뀌면 **과거 등급이 바뀐다** |

세 번째가 결정적이다. ingreed 가 "논문으로 감점하지 않는다 — 검색 시점에 따라
등급이 흔들린다"고 못 박은 것과 같은 자리다.

**대신:** 노트는 등급 **옆에 맥락**으로 붙는다("그날 무엇을 기록했나").
자동 분류는 **검색·연결에만** 쓴다.

**나중에 넣고 싶다면** — 사용자가 직접 선언하는 이진 플래그(예: "오늘 학습함")는
LLM 판단이 아니라 재현된다. 그때 축으로 승격할 수 있다. 자동 분류는 안 된다.

### 2.5 등급 컷의 근거

| 안 | 판정 |
|---|---|
| 본인 과거 분포 | ❌ **나쁜 습관이 기준선이 된다.** 매일 5시간 자면 5시간이 평균 → 개선 신호가 안 나온다. 초기 데이터도 없다 |
| 외부 공중보건 기준 | ✅ 채택. 인구 평균이라 개인차를 무시하지만, 요구가 "객관적 등급"이다 |
| 개인 프로필 기반 권장치 | ✅ 채택. **이미 코드에 있다** — `bmr`·`tdee`·`recommendedKcal`·`recommendedProteinG`·`recommendedWeeklyWorkouts`·`recommendedWorkoutMinutesPerDay` (`lib/domain/diet-read.ts`) |

**외부 기준을 임계값으로, 개인 프로필로 개인화한다.**
본인 과거 분포는 등급이 아니라 **추세 표시에만** 쓴다.

> ⚠ **외부 기준 수치는 이 문서에 적지 않았다.** 원문을 확인하지 않은 값을 넣지 않는다.
> §6-1 의 조사 항목이다.

## 3. 데이터 파이프 확장

현재 `/api/health/ingest` 가 받는 것은 `workout(kind, minutes)` 과
`metric(weight_kg, sleep_h)` **뿐이다**(`lib/health-ingest.ts`).

활동 축을 만들려면 **걸음수·활동에너지**가 필요하다. 이건 네이티브 앱 문제가 아니다 —
iOS 단축어가 HealthKit 에서 읽어 Bearer 로 POST 하는 구조라 **우리 쪽 스키마만 넓히면 된다.**

수면도 지금은 시간(h)뿐이다. 수면 단계·중도각성은 단축어가 줄 수 있는지 확인이 필요하다(§6-2).

## 4. IA 전환 — 탭 6개 → 3개

탐색의 단위가 **"도구"에서 "하루"로** 바뀐다.

| 지금 | 바뀐 뒤 | 비고 |
|---|---|---|
| 홈 · 식단 · 인박스 | **오늘** | 기록하고 보는 곳. **등급이 여기 산다** |
| (없음) | **돌아보기** | 과거의 날들 · 추세. `ratable:false` 인 날은 추세에서 빠진다 |
| 채팅 · 검색 | **묻기** | 내 기록·지식에 질문. 안에서 정확검색/종합답변을 가른다 |
| 설정 | (탭 아님) | 프로필 메뉴로 |

- **입력은 진입점 하나로 모은다.** 지금은 노트 담기·식사·운동이 각각 다른 폼이다.
  `lib/rpc/handlers.ts` 의 `handleDietChat` 에 이미 운동/식사를 가르는 휴리스틱이 있다 — 재사용한다.
- **기존 자유입력 경로는 남긴다.** ingreed 가 못 찾는 음식이 여전히 있다.

## 5. 하면 안 되는 것

- **등급·점수를 LLM 으로 산출하지 않는다.** 재현되지 않으면 이의제기에 답할 수 없다
- **행동적 결측을 재정규화하지 않는다**(§2.2) — 기록 안 한 날이 좋은 날이 된다
- **자동 분류 결과를 등급에 반영하지 않는다**(§2.4)
- **원문을 확인하지 않은 임계값을 넣지 않는다**(§2.5)
- **본인 과거 분포로 등급 컷을 잡지 않는다** — 나쁜 습관이 기준선이 된다
- **ingreed 의 제품 등급(A~E)을 하루 등급에 더하지 않는다** — 100g 기준·카테고리 상대값이다.
  그래서 `diet_meal` 에 `grade` 컬럼을 만들지 않았다

## 6. 미결 — 원문 확인이 필요한 것

1. **외부 공중보건 기준의 실제 수치** — 수면 권장시간, 주간 신체활동 권장량,
   당·나트륨·포화지방 일일 상한. 기관마다 값이 다르므로 **원문을 열어 확인**하고 출처를 남긴다
2. **iOS 단축어가 HealthKit 에서 실제로 내보낼 수 있는 항목** — 걸음수·활동에너지·
   안정시심박·수면단계. 문서가 아니라 실기기에서 확인해야 한다
3. **녹음 확장 시** — `REFACTOR_DIRECTION_WEB_2026-07.md §7-1` 이 미팅 녹음 파이프라인을
   전면 폐기했다. 폐기 사유는 "브라우저가 **시스템 오디오**를 캡처할 수 없다"였다.
   **본인 음성 메모라면 브라우저 마이크로 가능하므로 사유가 적용되지 않는다** — 되살릴 때 이 구분부터 확인할 것
